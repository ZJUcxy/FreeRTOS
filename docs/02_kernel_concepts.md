# 02 内核概念

## 2.1 调度模型

- **抢占式**：高优先级就绪立即打断低优先级
- **时间片**：同优先级可按 `configTICK_RATE_HZ` 轮转（需开启）
- **协作式**：仅在阻塞/主动让出时切换（一般不推荐作为主模式）

## 2.2 优先级设计经验

```text
最高: ISR 延迟处理（如 DMA 完成回调任务） / 安全停机
高  : 控制环（1ms）、硬实时采样整理
中  : 协议解析、命令处理
低  : 日志、统计、空闲扩展
Idle: 钩子、低功耗
```

规则：
1. 控制任务优先级 > 通信任务
2. 同优先级任务数量尽量少
3. 不要让低优先级任务持有高优先级任务需要的锁（优先级反转风险）

## 2.3 Tick 与时间

- `configTICK_RATE_HZ` 常用 `1000`（1ms）
- 周期任务优先用 `vTaskDelayUntil`，保证相位稳定
- 控制算法中的 `dt` 用名义周期，不要用“本次实际耗时”抖动值（除非做自适应）

## 2.4 临界区

| API | 场景 |
|-----|------|
| `taskENTER_CRITICAL` | 短临界，关调度/部分中断 |
| `vTaskSuspendAll` | 较长操作，仍允许中断 |
| `portDISABLE_INTERRUPTS` | 极少使用，尽量避免 |

临界区内禁止调用可能阻塞的 API。

## 2.5 上下文切换成本

STM32H7（Cortex-M7）切换开销通常微秒级；C6678（C66x）与 cache/流水线相关，切换更“贵”。  
因此 C66x 上更倾向：**少任务、粗粒度、大数据走共享内存 + 通知**。
